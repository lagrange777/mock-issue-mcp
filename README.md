# Mock Issue MCP

Отдельный учебный проект: mock HTTP API трекера задач и собственный MCP-сервер
на официальном Go SDK v1.7.0. Все данные вымышленные. Инструменты доступны только
для чтения; LLM и API-ключи для запуска не нужны.

## Запуск в Docker

```sh
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8090/healthz
```

- MCP endpoint: `http://127.0.0.1:8090/mcp`
- Транспорт: Streamable HTTP, stateless, JSON-ответы.
- Авторизация: отсутствует, порт опубликован только на loopback.
- Mock API: `http://127.0.0.1:8090/api/issues`
- Другой порт: `MOCK_PORT=8091 docker compose up -d --build`.
- Остановка: `docker compose down`.

В одном отдельном контейнере работают два слоя: HTTP API и MCP-адаптер.
При вызове инструмента адаптер выполняет настоящий HTTP-запрос к API через
loopback контейнера. Ответ SDK возвращает одновременно как `structuredContent`
и JSON-текст в `content`. MCP-сервер не подменяет результат заранее написанным ответом.

## Инструменты

| Инструмент | Параметры | Результат |
|---|---|---|
| `get_issue` | обязательный `key`, например `DEMO-101` | задача, исполнитель, статус, срок, `blockedBy` |
| `search_issues` | необязательные `project`, `status`, `priority`, `assigneeId`, `query`, `page`, `pageSize` | `items`, `total`, `page`, `pageSize`, `hasMore` |
| `get_issue_comments` | обязательный `key` | `key` и комментарии `items` с авторами и датами |
| `summarize_issues` | `issues` из поля `items` результата поиска, необязательный `title` | детерминированный Markdown, ключи и число задач |
| `save_issue_report` | безопасное имя `.md` и `content` из результата суммаризации | путь, размер и SHA-256 сохранённого отчёта |

Схемы входа и выхода доступны через `tools/list`. Неизвестные параметры
отклоняются. Статусы: `todo`, `in_progress`, `blocked`, `done`.
Приоритеты: `low`, `medium`, `high`, `critical`.
Фильтры поиска объединяются через И. Текст ищется в ключе, названии и описании
без учёта регистра. Страницы начинаются с 1, размер по умолчанию 5, максимум 50.
Задачи упорядочены по ключу; комментарии — от старых к новым.

## Данные и сценарии

В `data/seed.json` — 10 задач, 4 участника, 6 комментариев и проекты `DEMO`,
`OPS`, `EMPTY` (пустой). Даты фиксированы для воспроизводимой демонстрации;
если нужна актуальная просрочка, измените сроки в JSON.

Основной сценарий: «Почему заблокирована оплата и кто может помочь?»

1. `get_issue({"key":"DEMO-101"})` возвращает блокировку на `DEMO-100`.
2. `get_issue({"key":"DEMO-100"})` показывает задачу получения тестового ключа
   и ответственного Алексея.
3. `get_issue_comments({"key":"DEMO-100"})` сообщает, что заявка уже отправлена
   провайдеру; есть договорённость о следующем действии.

Дополнительные сценарии:
- `search_issues({"project":"DEMO","status":"blocked","pageSize":2})` — несколько страниц;
- `search_issues({"project":"EMPTY"})` — корректный пустой результат;
- `get_issue({"key":"DEMO-999"})` — ошибка «Задача не найдена»;
- `search_issues({"status":"unknown"})` — ошибка входной схемы;
- `DEMO-106` зависит от `DEMO-102` и `OPS-201`: пример межпроектных зависимостей.

Каталог `data` подключён в контейнер только для чтения. Изменяйте JSON на хосте:
API перечитывает и проверяет его на каждом запросе, пересборка не требуется.
Проверяются уникальность ключей, исполнители, проекты, даты и существование
зависимостей. Имена исполнителей и авторов вычисляются по `users`.
Некорректный JSON или битые ссылки дают HTTP 503, а healthcheck становится
неуспешным. Для сброса данных восстановите `data/seed.json` из Git.

## HTTP API

```sh
curl http://127.0.0.1:8090/api/issues/DEMO-101
curl 'http://127.0.0.1:8090/api/issues?project=DEMO&status=blocked&page=1&pageSize=2'
curl http://127.0.0.1:8090/api/issues/DEMO-100/comments
```

Ошибки: 400 — неверный ключ/фильтр/пагинация; 404 — задача не найдена;
503 — источник данных недоступен. MCP преобразует ошибки API в `isError: true`,
а не в успешный пустой ответ. HTTP-вызов инструмента ограничен 5 секундами.

## Проверка MCP

Для клиента и локальной разработки нужен Go 1.25+.

```sh
go run ./cmd/mcp-check
go test -race ./...
go vet ./...
```

`mcp-check` подключается к запущенному контейнеру, печатает список трёх
инструментов и выполняет реальные `tools/call`: чтение задачи, её блокирующей
задачи, комментариев и поиск. Для другого адреса используйте `-url`.
Тесты поднимают локальные HTTP/MCP-серверы, проверяют схемы, результаты,
пагинацию, ошибки и факт HTTP-обращения инструмента к API.

Локальный запуск без Docker:

```sh
go run ./cmd/mock-issue-mcp
```

Переменные: `LISTEN_ADDR` (по умолчанию `127.0.0.1:8090`),
`DATA_PATH` (`data/seed.json`), `TRACKER_API_URL` (по умолчанию собственный
loopback URL). Последняя позволяет направить MCP-адаптер на отдельную реализацию
того же API или тестовый HTTP-сервер для сценариев 503/тайм-аута.

## Подключение к чат-приложению

Из приложения, запущенного непосредственно на хосте, используйте URL
`http://127.0.0.1:8090/mcp`, поле Bearer-ключа оставьте пустым.
Если чат работает в другом Docker-контейнере, его `localhost` указывает на него
самого. Для связи потребуется общая Docker-сеть и адрес сервиса; текущий
чат-клиент также разрешает HTTP только на loopback. Настройка этой связи и
цикл вызовов инструментов агентом — следующий этап, здесь чат не изменяется.

## Подключение к codex-chat-cli

Compose создаёт общую сеть `codex-mcp`. Сначала запустите этот проект через
`docker compose up -d --build`, затем приложение `codex-chat-cli`.
В приложении откройте MCP → Mock Issue Tracker, сохраните адрес
`http://mock-issue-mcp:8090/mcp` без ключа, проверьте подключение,
отметьте три инструмента, включите «Использовать в чате» и сохраните разрешения.

Пример запроса: «Почему заблокирована задача DEMO-101 и кто может помочь?»
Агент читает DEMO-101, зависимость DEMO-100 и её комментарии, затем объясняет
блокировку. Фактические вызовы и результаты видны под ответом.

Для проверки композиции разрешите `search_issues`, `summarize_issues` и
`save_issue_report`, затем попросите найти заблокированные задачи DEMO, собрать
Markdown-отчёт и сохранить его как `blocked-demo.md`. Последний инструмент пишет
только новые файлы в Docker-том `reports`; пути и перезапись чужого содержимого
запрещены. Повтор того же вызова идемпотентен.
